# Device icons verification

The devices batch adds MonitorCheck, MonitorCog, LaptopMinimalCheck, SmartphoneCharging, SmartphoneNfc, Keyboard, Cctv, Projector, Vibrate, and EvCharger at base `b0d06056317e57c783780aa968f4b6872c4bfe4e`.

The recipes and reference components use [Lucide Animated revision 4662fff2b60fdcf4751b32013606756caf7c4c26](https://github.com/pqoqubbw/icons/tree/4662fff2b60fdcf4751b32013606756caf7c4c26/icons). Every copied reference was checked byte-for-byte against the read-only archive after reversing its documented import changes. The class utility import points to the fixture equivalent. Keyboard also uses the fixture's scoped random stream.

## Implementation and compatibility

MonitorCheck and LaptopMinimalCheck share a check recipe with independent opacity and normalized path-length transitions. SmartphoneCharging and EvCharger share their looping opacity recipe. MonitorCog reuses the existing cog spring. SmartphoneNfc reuses the signal sampler. Cctv and Vibrate reuse the SVG-parts sampler. Projector uses the existing cancellable sequence for its rays while the body pulse runs concurrently. No common public API or dependencies change.

Projector initializes its normalized dash to a complete stroke before its scalar fade. Without this initialization, CSS interpolates discretely from `none` to the hidden dash. The original React path-length control starts from 1. Its hidden opacity and path-length tracks use Motion's implicit 300 ms curve. The 400 ms redraw waits for all hidden tracks to complete. Stop, replay, removal, and reduced motion cancel pending stages.

Keyboard preserves the source's per-key delay distribution, 1500 ms opacity keyframes, reverse repeat, and immediate stop reset. The common start method replays Keyboard even when already playing. The original React state setter ignores repeated starts while hovered. An interrupted replay starts from the declared opacity 1. The comparison uses the production recipe factory in an isolated custom element with a fixed stream of 0.5. It receives the SVG rendered by the Astro adapter. The original Keyboard reference uses the same scoped stream. Production uses Math.random. No global random function is patched.

## Browser and recipe evidence

All browser runs use installed Chrome, `ICON_TEST_PORT=45391`, and at most two workers. The focused file uses one worker because Playwright runs this file sequentially.

- The initial MonitorCheck regression failed with `Expected: 0.5, Received: 1` before the recipe existed. It passed after the check's independent 400 ms transitions were added.
- `pnpm check` passed both Astro checks with zero errors, warnings, and hints, plus TypeScript.
- `ICON_TEST_PORT=45391 pnpm test tests/devices.spec.ts --workers=2` reported `110 passed (2.1m)`. It checks all idle SVGs and native links without JavaScript, hover, instance isolation, rapid replay, stop continuity, removal, and reduced motion. Keyboard has dedicated immediate-reset checks at 50, 900, 1800, and 2500 ms. A separate check observes random delays, reverse repeats, and explicit repeated starts. Sequence tests observe clean opacity, dashes, and transforms after cancellation during both stages.
- The comparison route is `/devices-comparison/` at 14, 16, 24, and 28 px. The eight single-stage recipes compare entry plus captured returns from 150, 650, and 1600 ms. SmartphoneNfc and Projector compare entry and captured return during both stages. SmartphoneNfc completes its fade naturally before spring sampling so the original native completion velocity is preserved. Projector uses explicit phase completion to advance the original async controls.
- `ICON_TEST_PORT=45391 pnpm test tests/devices-replay.spec.ts --workers=1` reported `9 passed (18.1s)`. Each progressive recipe replays during a return, preserves its pose, resumes movement, and cleans up. After the return completes, the restarted pose matches a fresh instance at the same sampled time.
- Those comparisons measured at most 0.000732 screen pixels of geometry difference and 0.002125 of normalized paint difference. Return sampling captures poses and resets reference velocity. Actual interrupted spring velocity parity remains unmeasured.

## Complete validation

`ICON_TEST_PORT=45391 pnpm validate --workers=2` passed both Astro checks, TypeScript, one forced build, and inspection of 334 icons across 671 bundle cases. It stopped at one inspector negative test because the new single-icon cases preceded ArrowLeft, which supplies the shared-CSS baseline. Keeping ArrowLeft first corrected the test without changing its assertions. The remaining steps reused the same output, with no second forced build.

- `ICON_TEST_PORT=45391 pnpm test:bundle` passed all five tests, including rejection of icon-specific CSS in the baseline.
- `ICON_TEST_PORT=45391 pnpm test:fixture` passed all three cache tests. The fixture preparation reused matching sources and output.
- `ICON_TEST_PORT=45391 pnpm exec tsc --noEmit` passed after the replay coverage was added.
- `ICON_TEST_PORT=45391 pnpm test --workers=2` completed the full Chrome suite with `2758 passed (31.4m)` and one timeout. All 119 devices scenarios passed. The existing Grips comparison exhausted its unchanged 30000 ms test budget at the final Play all click after its numerical assertions. The grips recipe and test were not modified.
- `ICON_TEST_PORT=45391 pnpm test tests/grips.spec.ts --grep 'all grips match normalized native references' --workers=1` passed the isolated comparison. The test itself took 13.6 seconds with the same assertions and 30000 ms budget. It measured zero opacity difference and 0.000061 screen pixels of geometry difference. No timeout was increased and no assertion was weakened. The isolated pass does not establish the cause of the full-run timeout.
